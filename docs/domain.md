# 领域资料

## 目标

亲子健康跑的赛事保障系统覆盖**报名 → 检录 → 检查点 → 医疗处置 → 离场**全链路：

- **五公里亲子组**持续校验监护关系。家长已经过终点而孩子芯片停在补给站时，保障席要立刻拿到“去哪找人、联系谁”，普通志愿者只能看到该去找谁、人最后在哪，不能接触家庭电话或未成年人的完整轨迹。
- **十公里个人组**独立计时、独立排名。
- 检录、检查点读刷、医疗处置、离场确认共同组成一条**可信时间线**。
- 芯片补传、人工更正、重复刷卡都**保留原始事实**，但对同一参赛者 × 检查点只形成**一个到达状态**。
- **医疗转运**是成绩终局：状态锁定为 `medical_evacuation`，之后补到的终点芯片不再产生成绩。
- 指挥席按**最后可信位置**生成寻找清单；家长只查自己的家庭；公开成绩只呈现比赛所需信息；赛后汇总不允许反推出未成年人的精确路线。

## 标识与隐私约定

- 对外交换只使用不含真实身份的引用编号：`event_ref`、`checkpoint_ref`、`family_ref`、`runner_ref`、`bib`、`public_label`、`group_code`。
- 家庭联系方式（`contact_channel`）单独存在 `families` 表，只有 `command` 角色的寻找清单返回；志愿者清单、家长视图、公开成绩、汇总均不含该字段。
- 医疗口述等敏感材料不落原文，只保存 `detail_digest`（`sha256`）。
- 交换时间一律使用**带偏移量的 ISO 8601** 字符串；库内另存 `instant_ms` 纪元毫秒用于确定性排序。原始 `occurred_at` 永不被改写。
- 访问令牌只保存 `sha256` 摘要，明文仅在签发时返回一次。

## 事实与状态分离

`raw_events` 是**只追加**的事实流，来源 `source` 区分：`live`（实时读刷）、`retransmitted`（设备补传）、`duplicate`（重复刷卡）、`manual`（人工）。

投影表 `arrival_states`、`runner_status`、`supervision_alerts` 都可由事实**完整重建**（每笔入库后在事务内重放该参赛者全部事实）。单一到达状态的推导规则：

1. `chip` / `checkin`（含补传）按发生时间取**最早一笔**作为到达——重复刷卡天然折叠，但重复事实仍留痕并通过 `duplicate_of` 关联；
2. `manual` + `void` 是**作废锚点**：该检查点此前的到达全部作废，此后的真实读刷重新成立；
3. `manual` + `set` 是**人工权威锚点**：同一时段内压过芯片读刷，状态标记 `corrected = 1`。

客户端可用 `client_event_id` 做幂等上报，网络重放返回首次入库的事实，不产生第二条记录。

## 监护关系校验

亲子组以本家庭**最远监护人**到达的检查点位置为基准：

- 未成年人未到达的每个前置检查点生成一笔开放告警（`supervision_alerts`，按家庭/孩子/检查点唯一）；
- 孩子补刷追上报到、孩子完赛、孩子被转运，或全家都已完赛/离场时关闭告警；
- 寻找清单优先列监护分离的未成年人（`reason = supervision_gap`），并合并“赛段超过 `stage_sla_seconds` 未出现”的超时在途选手（含十公里个人）。

## 角色与读取口径

| 角色 | 令牌 | 能写 | 能读 |
| --- | --- | --- | --- |
| `command` 指挥/保障席 | 全局或单赛事 | 全部，含人工更正 | 寻找清单（含联系方式）、完整事实时间线、汇总、家庭视图 |
| `marshal` 普通志愿者 | 绑定赛事 | chip/checkin/medical/exit | 脱敏寻找清单：号码、脱敏称呼、最后可信位置、原因/标志 |
| `guardian` 家长 | 绑定家庭 | — | 仅自己家庭的进度与开放告警 |
| 公开 | 无 | — | 成绩榜 |

- 十公里成绩：名次、号码、公开名、出发/到达时间、用时。
- 五公里成绩：只公布**家庭整体**（组号、公开队名、人数、家庭净用时），不拆到未成年人个人。
- 汇总：仅按组别给报名/检录/在途/完赛/转运/离场计数与开放告警数，**不提供任何检查点级分布**。

字段名称属于稳定接口约定（见 `contracts/entities.json`），运行时数据文件位置由 `DATABASE_PATH` 决定。
